# 个人展示网站后端设计

本期后端只负责展示数据、L07 与 L08 的维护、外部 API 接入状态和可见性控制。采用单站点管理，在现有 NeoBlog 后端中增加展示站接口，复用数据库与管理员鉴权；访客只读取允许公开的数据，站主登录后维护内容和检查同步结果。

本文为待实现的接口与数据约定。展示范围和字段口径沿用[数据来源设计](个人展示网站数据来源候选稿.md)，其中 L07、L08 在本后端直接读写，无须再经过定时同步。

## 服务结构与范围

```text
展示页面 ── 公开读取接口 ── 可见性过滤 ── 本地内容与最近成功缓存
管理页面 ── 管理员鉴权 ── 内容维护、数据查看、可见性设置、手动刷新
                                      │
                        定时同步与来源适配器
                                      │
                          Steam / Bangumi / GitHub

NeoBlog 创作内容 ── 现有文章与标签服务 ── 展示站数据适配
```

新增功能放在 NeoBlog 后端的独立 `showcase` 模块中，路由、业务服务和来源适配器分开即可。使用现有 Express、TypeScript、Prisma 和 MySQL，不另建鉴权服务、Redis、消息队列或微服务。同步调度先在单个后端进程内运行，部署一份调度实例。

外部数据由服务端适配、缓存，公开请求不触发上游采集。NeoBlog 内容调用现有文章与标签服务，不通过 HTTP 请求自己。博客文章仍在原博客后台编辑；展示站后台只管理这些内容是否展示。

一期不增加访客账号、注册、评论、复杂角色权限、审批发布、历史版本或监控告警平台。API 状态只是后台的一张来源列表和各模块最近同步结果。

## 管理入口

后台只需要四个页面。

| 页面 | 站主可执行的操作 |
| --- | --- |
| 当前状态 L07 | 修改当前描述、有效期；设置公开或隐藏 |
| 学习目标 L08 | 新增、编辑、删除目标；更新进度与状态；调整顺序；设置单条可见性 |
| 数据与 API 状态 | 查看来源和模块最近同步结果、更新时间、数据数量；浏览标准化缓存；手动刷新指定模块 |
| 展示设置 | 开关各展示模块；在支持的列表中隐藏或恢复指定条目 |

来源状态与展示开关分开：隐藏一个模块不会删除内容，也不表示 API 发生故障。默认仍按原计划同步，方便后台查看最新数据；没有额外的同步开关。

## 数据模型

复用现有 `User` 及鉴权数据，新增以下五张表。数据库字段可以沿用 NeoBlog 的命名风格，接口统一使用 camelCase。时间存 UTC，API 使用带 `Z` 的 ISO 8601 字符串，由页面转换为展示时区。

| 表 | 用途 | 主要字段 |
| --- | --- | --- |
| `personal_status` | L07 单例，固定 `id=1` | `text`、`visible`、`expiresAt`、`updatedAt` |
| `learning_goals` | L08 目标列表 | `id`、`title`、`description`、`progress`、`status`、`visible`、`sortOrder`、`createdAt`、`updatedAt` |
| `showcase_modules` | 固定模块及展示设置 | `id`、`source`、`visible`、`updatedAt` |
| `showcase_cache` | 外部模块最近成功数据与同步状态，每模块一条 | `moduleId`、`payload`、`lastAttemptAt`、`lastSuccessAt`、`nextAttemptAt`、`lastResult`、`lastErrorCode`、`lastErrorMessage`、`upstreamStatus`、`durationMs` |
| `showcase_item_visibility` | 外部列表单条可见性覆盖 | `moduleId`、`itemId`、`visible`、`updatedAt`；前两项联合唯一 |

`payload` 保存适配后的 JSON 数据，只保留当前快照。完整采集成功后，在事务中替换数据和成功时间；失败只更新本次请求状态，不覆盖最近成功数据。同步参数、字段白名单、刷新间隔和模块名称放在代码配置中，不做通用接口配置编辑器。

### L07 当前状态

| 字段 | 约定 |
| --- | --- |
| `text` | 当前在做什么，纯文本，最多 500 字；空字符串表示清空描述 |
| `visible` | 整条 L07 是否公开，初始为 `false` |
| `expiresAt` | 可为 `null`，表示持续有效；否则必须是保存时之后的时间 |
| `updatedAt` | 服务端生成，每次修改时更新 |

过期后整条 L07 退出公开展示；后台仍能查看和修改。有效期在读取时判断，无须清理任务。只修改文字不会自动延长有效期，重新发布已过期内容时必须更新或清空 `expiresAt`。

### L08 学习目标

| 字段 | 约定 |
| --- | --- |
| `id` | 服务端生成的稳定 ID，不使用列表下标 |
| `title` | 必填纯文本，1 至 100 字 |
| `description` | 可选纯文本，最多 1000 字 |
| `progress` | `null` 或 0 至 100 的整数；`null` 表示未设置百分比 |
| `status` | `planned` 计划中、`active` 学习中、`paused` 暂停、`completed` 已完成 |
| `visible` | 单条公开开关，新建默认 `false` |
| `sortOrder` | 非负整数，越小越靠前；同值按 ID 排序 |

新建目标只要求 `title`，其余默认值为 `description: null`、`progress: null`、`status: planned`、`visible: false`、`sortOrder: 0`。状态与进度由站主分别维护，不自动换算。`completed` 表示归档到已完成分组，保持记录；公开默认列表排除已完成目标，使用 `status=completed` 可读取公开的已完成目标。删除为永久删除，后台在操作前提示。

| `github.contributions` | G02 贡献日历 | 否 |
| `github.activity` | G03 最近公开活动 | 是，事件 ID |
| `github.pinned` | G04 置顶仓库 | 是，仓库 ID |
| `github.repositories` | 配置账号名下全部公开仓库，含 Fork 和归档仓库 | 是，仓库 ID；独立于置顶仓库设置 |
| `github.languages` | G07 置顶仓库语言构成 | 跟随对应置顶仓库的可见性 |

这些 ID 是展示站内部约定，来源适配时映射到已有接口。模块初始化为隐藏，由站主逐项开启；列表条目没有覆盖记录时继承模块公开设置。只允许固定模块和对应条目类型，不接受用户提交任意 URL 作为代理目标。

## 管理鉴权

复用 NeoBlog 现有登录流程和 `authenticate`、`requireAdmin`。所有 `/api/showcase/admin/*` 路由必须同时通过两者；未登录返回 `401`，已登录但不是管理员返回 `403`。校验沿用现有账号状态、最新角色与 `token_version`，不单独手工验签。

| 已有接口 | 用途 |
| --- | --- |
| `GET /api/auth/natayark` | 跳转至现有 OAuth 登录 |
| `GET /api/auth/natayark/callback` | 处理登录回调 |
| `GET /api/auth/me` | 读取登录用户，管理页面判断是否可进入 |
| `POST /api/auth/logout` | 退出并沿用现有令牌撤销行为 |

站主使用现有管理员账号；一期不增加账号管理页面和新的权限角色。管理页面与 API 通过同源反向代理部署，浏览器使用 HttpOnly Cookie；生产 Cookie 使用 `Secure` 和 `SameSite=Lax`。新增管理写入请求校验 `Origin` 为配置的管理页面来源，缺失或不匹配均拒绝，避免 Cookie 被其他站点利用。登出请求也执行此校验。

Steam Key、GitHub Token 等通过服务端环境变量配置。后台只显示凭据“已配置”或“未配置”，不提供明文读取接口。日志和错误响应不包含 Token、Cookie 或完整上游鉴权请求。

源码依据：[现有鉴权中间件](E:/NeoBlog/backend/middleware/auth.ts)、[现有鉴权路由](E:/NeoBlog/backend/src/index.ts:115)、[现有用户模型](E:/NeoBlog/backend/prisma/schema.prisma:14)。Cookie 与 Origin 规则是本设计的实施要求，不能仅因复用现有登录就视为已经满足。

## API 请求端点

### 公开读取

| 方法与路径 | 返回内容 |
| --- | --- |
| `GET /api/showcase/modules` | 当前开启的模块 ID 与公开可用状态；不返回后台错误详情 |
| `GET /api/showcase/modules/:moduleId/data` | 指定外部模块的标准化展示数据，执行可见性过滤 |
| `GET /api/personal-status` | 有效且公开的 L07；没有可展示内容时返回 `data: null` |
| `GET /api/learning-goals` | 公开目标列表，支持状态筛选及分页 |

列表参数统一为 `page`、`limit`，默认 1 和 20，`limit` 最大 100。Bangumi 支持 `category=watched|watching|want|on_hold|dropped`，默认 `watched`；目标支持 `status=planned|active|paused|completed`，未提供时返回前三种状态。其他筛选参数按模块白名单校验，不向上游透传任意参数。

通用模块数据接口只接受上表的外部模块，L07、L08 通过专用接口读取。单对象数据不分页。外部列表先执行既定排序及隐藏过滤，再计算数量和分页；`total` 只能统计过滤后的结果。

外部模块关闭或 ID 不存在时返回 `404`，不附带缓存内容；开启但没有可用缓存时返回 `503`。成功取得的空列表返回 `200`，不能误判为故障。已知上游撤回公开权限的模块暂时按无可用数据处理。

### 全部 GitHub 公开仓库

`GET /api/showcase/modules/github.repositories/data?page=1&limit=20` 返回配置的 `GITHUB_USERNAME` 名下全部公开仓库，含 Fork 和归档仓库；不包含仅参与的其他账号或组织仓库。服务端使用 GitHub 的 [List repositories for a user](https://docs.github.com/en/rest/repos/repos#list-repositories-for-a-user)，限定 `type=owner` 并逐页采集；不要求 `GITHUB_TOKEN`，配置后会用于请求鉴权。即使 Token 可以读取私有仓库，也只缓存明确公开的条目。

| 字段 | 含义 |
| --- | --- |
| `id`、`name`、`fullName` | 仓库数字 ID、名称、含所有者的完整名称 |
| `description`、`url`、`homepage` | 简介、GitHub 仓库链接、项目主页；简介和主页可为 `null` |
| `stars`、`forks`、`language` | Star 数、Fork 数、主要语言；语言可为 `null` |
| `fork`、`archived` | 是否为 Fork、是否归档 |
| `defaultBranch`、`topics` | 默认分支、主题标签数组 |
| `createdAt`、`updatedAt`、`pushedAt` | 创建、更新和最近推送时间，ISO 8601；推送时间可为 `null` |

仓库先按更新时间倒序、同时间按 ID 升序排列，再执行单条隐藏过滤与本地分页；返回标准 `pagination` 和 `meta`。该模块与 `github.pinned`、`github.languages` 的开关及隐藏设置独立，隐藏置顶条目不会自动隐藏全部仓库列表中的同一条目。

无需表结构迁移，重启后端即通过模块初始化添加该模块，默认隐藏；在管理页的展示设置中开启后才能公开读取。管理数据入口为 `GET /api/showcase/admin/modules/github.repositories/data`，刷新入口为 `POST /api/showcase/admin/modules/github.repositories/refresh`，开关与条目隐藏使用现有通用管理接口。现有管理页面根据模块目录自动展示该模块。首次采集前公开读取返回 `503`，定时采集依照 `SYNC_ENABLED` 执行，也可手动刷新。

### 全部 GitHub 仓库语言统计

`GET /api/showcase/modules/github.language-stats/data` 返回配置账号名下全部公开及私有仓库的语言汇总，含 Fork 和归档仓库，不包含组织或仅参与的其他账号仓库。由服务端先通过 [Get the authenticated user](https://docs.github.com/en/rest/users/users#get-the-authenticated-user) 校验 Token 身份及公开、私有仓库总量，再通过 [List repositories for the authenticated user](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user) 指定 `visibility=all&affiliation=owner` 完整分页，逐仓库读取 [List repository languages](https://docs.github.com/en/rest/repos/repos#list-repository-languages) 的代码字节数。每批最多四个语言请求，完整采集仍受单模块 60 秒预算约束。

| 字段 | 含义 |
| --- | --- |
| `repositoryCount` | 纳入统计的所有仓库数，包含空仓库 |
| `repositoriesWithLanguages` | 至少有一种语言字节数大于零的仓库数 |
| `totalBytes` | 所有仓库各语言代码字节之和 |
| `languages[].name` | 语言名称 |
| `languages[].bytes` | 该语言在所有仓库中的代码字节之和 |
| `languages[].percentage` | 该语言字节数占总字节数的百分比，四舍五入至两位小数 |
| `languages[].repositoryCount` | 具有该语言且字节数大于零的仓库数 |

`data` 是单个汇总对象，返回标准 `meta`，不分页；语言按总字节数倒序、相同字节数按名称排序。无仓库或无语言数据均返回有效零统计，`languages: []`，不会将空结果判为失败。占比由于四舍五入可能不恰好合计 100%，表示仓库代码构成，不表示个人熟练度；Fork 与归档也纳入统计。

缓存与管理响应也只保留上述汇总字段；私有仓库名称、链接、ID 和逐仓库语言明细仅在采集期间使用，不写入缓存、日志或错误信息。公开接口重新投影嵌套语言字段。该汇总经用户确认可在开启模块后公开展示，独立于置顶仓库和公开仓库列表的隐藏设置；隐藏某个公开仓库条目不会将其语言从全量统计剔除，也不提供逐仓库隐藏操作。

必须配置同一账号的 `GITHUB_USERNAME` 与 `GITHUB_TOKEN`。classic PAT 需 `repo` 以读取全部公开、私有仓库，并需 `read:user` 取得 `/user` 响应的 `owned_private_repos`；fine-grained PAT 应选择全部仓库并授予 Metadata 读取权限，且 `/user` 必须提供该私有仓库计数，否则报 `GITHUB_SCOPE_UNVERIFIED`，不能验证全量数据。账号不匹配报 `GITHUB_ACCOUNT_MISMATCH`，仓库数量不足报 `GITHUB_REPOSITORIES_INCOMPLETE`。采集前后核对公开及私有仓库总量，期间发生数量变化报 `REPOSITORIES_CHANGED`，分页重复或缺页同样拒绝提交。

该模块默认隐藏，无需数据库迁移，重启后端自动注册。管理读取和刷新路径分别为 `GET /api/showcase/admin/modules/github.language-stats/data`、`POST /api/showcase/admin/modules/github.language-stats/refresh`；模块开关沿用通用 `PATCH` 管理接口。公开读取仅查询缓存，不请求 GitHub。确认账号或仓库权限不足、仓库 404 或移除 Token 时停止公开旧汇总；普通网络失败保留最近完整统计，同步成功后恢复可用。

### 管理读取与维护

以下路径均以 `/api/showcase/admin` 为前缀。

| 方法与路径 | 功能 |
| --- | --- |
| `GET /personal-status` | 查看 L07，包含隐藏和过期内容；不存在时返回 `null` |
| `PUT /personal-status` | 完整保存 L07，允许首次创建；请求包含全部可编辑字段 |
| `GET /learning-goals` | 查看全部目标，支持状态、可见性筛选和分页 |
| `POST /learning-goals` | 新增目标，返回 `201` |
| `PATCH /learning-goals/:id` | 修改目标字段、进度、状态、顺序或可见性 |
| `DELETE /learning-goals/:id` | 删除目标，返回 `204` |
| `GET /sources` | 查看 Steam、Bangumi、GitHub、NeoBlog 的汇总状态 |
| `GET /modules` | 查看全部模块开关与各模块同步结果 |
| `GET /modules/:moduleId/data` | 查看未做展示隐藏过滤的标准化数据；同样支持分页 |
| `PATCH /modules/:moduleId` | 设置模块 `visible`，请求仅允许这一字段 |
| `POST /modules/:moduleId/refresh` | 手动刷新指定外部模块，更新本地缓存与状态 |
| `PUT /modules/:moduleId/items/:itemId/visibility` | 设置受支持条目的 `visible` |

管理数据接口接受外部模块，并在每条列表数据上补充 `itemId` 和最终展示用的 `visible`。L07、L08 使用专用管理接口。`PATCH` 未提供的字段保持原值；未知字段、错误类型和无效枚举返回 `400`，不接受客户端指定系统时间、来源或鉴权字段。

单条隐藏接口只接受具有稳定 ID 的受支持条目；新设置要求条目当前存在，已有覆盖记录允许恢复可见。恢复为 `true` 时可删除覆盖记录，回到继承状态。同步只更新数据，不清除隐藏设置，避免条目重新出现时意外公开。

### 响应格式

除 `204` 和已有 OAuth 跳转外，新增接口使用统一包装。以下为外部列表公开读取示例，字段按实际模块变化：

```json
{
  "success": true,
  "data": [{ "appId": 730, "name": "Counter-Strike 2" }],
  "pagination": { "page": 1, "limit": 20, "total": 1 },
  "meta": {
    "moduleId": "steam.games",
    "source": "steam",
    "updatedAt": "2026-10-09T08:00:00Z",
    "freshness": "fresh"
  }
}
```

`freshness` 为 `fresh|stale|unavailable`，表示数据是否满足刷新期限，与最后一次请求是否成功分别计算。L07、L08 的更新时间来自内容记录；不返回虚构的上游同步时间。分页包装仅用于列表。

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "progress 必须为 0 至 100 的整数或 null"
  }
}
```

新增接口的错误状态统一为：`400` 参数无效、`401` 未登录、`403` 权限或来源校验失败、`404` 资源不存在、`409` 同一模块正在刷新、`429` 请求过于频繁、`502` 手动刷新失败、`503` 公开数据不可用、`500` 内部错误。公开错误只说明模块暂不可用，具体上游错误留在管理接口。

## API 状态与同步规则

状态表示最近采集结果，不声称实时探测上游是否在线。`GET /sources` 返回来源、凭据是否配置、汇总状态、最近尝试时间和最近成功时间；`GET /modules` 返回各模块的具体状态、数据数量、下一次尝试时间、耗时和脱敏错误。

`lastResult` 取值为 `never|ok|timeout|rate_limited|auth_error|private|error`。数据新鲜度另按时间计算：最后请求成功也可能已经过期，最后请求失败也可能仍有可用缓存。同步中的标识由进程内任务状态补充，进程重启后不留下永久的“刷新中”。

来源汇总为 `unconfigured|unknown|ok|degraded|unavailable`：未配置必需参数为 `unconfigured`，尚未采集为 `unknown`，全部模块数据新鲜且最近请求正常为 `ok`，部分异常或存在可用旧数据为 `degraded`，全部模块无可用数据为 `unavailable`。必须保留模块明细，例如 GitHub 普通资料成功而贡献图鉴权失败时不能显示整个来源正常。

NeoBlog 在本方案中是内部数据源，后台明确标为“本地服务”；状态记录文章与标签读取结果，不冒充外部 HTTP 请求。读取失败只影响创作模块。

| 模块 | 默认刷新间隔 | 失败时的公开行为 |
| --- | --- | --- |
| Steam 在线与正在游玩 | 2 分钟 | 最近成功超过 5 分钟后停止展示旧状态 |
| Steam 名片 | 6 小时 | 临时故障可使用旧缓存并标记时间 |
| Steam 游戏库 | 1 小时 | 临时故障可使用旧缓存并标记时间 |
| Bangumi 五类收藏 | 1 小时 | 保留最近完整快照 |
| GitHub 名片、置顶项目与全部公开仓库 | 6 小时 | 临时故障可使用旧缓存并标记时间 |
| GitHub 贡献图与语言构成 | 24 小时 | 临时故障可使用旧缓存并标记时间 |
| GitHub 全部仓库语言统计（含私有） | 24 小时 | 普通网络失败保留完整汇总；确认权限不足时停止公开旧汇总 |
| GitHub 最近公开活动 | 30 分钟 | 临时故障可使用旧缓存并标记时间 |
| NeoBlog 文章、标签与归档 | 15 分钟 | 临时读取故障可使用旧缓存并标记时间 |
| L07 与 L08 | 无同步任务 | 保存后直接读取数据库 |

普通模块超过默认刷新间隔标记 `stale`，旧数据最多保留公开 7 天，之后为 `unavailable`；后台仍可查看快照。Steam 在线状态采用上述 5 分钟限制。上游限流时遵守其返回的最早允许重试时间，手动刷新也不能绕过。

单次上游请求默认超时 10 秒，单模块完整刷新预算 60 秒；超出预算保留旧快照并记录失败。五类 Bangumi 收藏均获取完整分页后才发布新快照；游戏库同样取齐后再合并排序。置顶仓库更新成功后刷新对应语言数据，未完成时将语言模块标记为过期，不能沿用已移除仓库的公开结果。

全部仓库以每页最多 100 条获取所有分页，依据 GitHub `Link` 的下一页关系继续；缺少该响应头时继续请求整页结果的下一页。为减少分页期间更新引发的条目移动，上游按完整名称排序；发现重复 ID、空的中间页、响应格式异常或分页请求失败时拒绝提交新快照，保留最近完整结果。成功的空列表正常清除旧仓库，重新同步不会重置条目隐藏设置；完整采集确认已删除或转私有的仓库不再出现在新结果中。

手动刷新使用同一套采集逻辑，等待本次结果返回：成功 `200`，失败 `502`；不增加后台任务查询接口。同一模块已有任务时返回 `409`，两次刷新尝试至少间隔 30 秒，否则返回 `429` 并带 `Retry-After`。定时任务同样避免重入，失败后等待下一次允许的尝试，不无限重试。管理接口等待时间和反向代理超时需覆盖刷新预算。

## 可见性与数据一致性

公开数据必须同时满足模块开启、条目可见、数据有效三个条件。L07 额外检查有效期，L08 额外应用请求的状态筛选。管理员可查看隐藏内容，公开接口在管理员登录时仍执行相同的过滤规则，预览隐藏数据必须使用管理读取接口。

标签、归档和文章数量均基于展示站可见的文章计算；文章模块关闭时，标签与归档也停止公开。隐藏置顶仓库后，也隐藏该仓库的语言数据；置顶模块关闭时，语言模块也停止公开。关联模块自身的开关仍须开启才能展示。隐藏条目从列表数量中移除。服务端按字段白名单输出，不能直接公开整个 `payload` 或把后台错误带到前台。

可见性检查在每次公开读取时执行，不依赖下一次同步。一期公开 JSON 接口使用 `Cache-Control: no-store`，前端不使用持久数据缓存；修改隐藏设置后，后续请求立即排除内容，已经打开的页面在再次读取时更新。无法撤回访客此前已经取得的数据。

上游明确返回内容删除或公开权限撤回时，立即停止公开相应快照，保留后台排查所需的脱敏状态。普通网络错误、Token 失效与隐私撤回分别处理，不能都按空列表覆盖；成功空结果则正常替换旧列表，避免已删除内容继续出现。HTTP 状态含义由各来源适配器判断，不统一把所有 `403` 当作隐私撤回。

可见性只控制本展示站的 API 输出。隐藏 NeoBlog 文章不会修改原博客公开范围，外部主页和公开图片链接也仍受原平台规则控制。

## 实施顺序与验收

先新增五张表与模块初始化，再接入现有管理员鉴权和 L07、L08 维护接口；随后完成各来源适配与缓存，最后接入后台状态页及可见性设置。数据库迁移、备份和部署继续使用 NeoBlog 的现有流程。

验收覆盖以下场景即可，不建设额外测试平台：

1. 未登录不能读写管理接口；普通成员不能维护内容；管理员退出或被禁用后管理请求失效。
2. L07 可保存、清空、隐藏，过期后公开接口返回 `null`；L08 可维护进度、归档、排序和单条可见性。
3. 外部数据请求失败不会覆盖成功快照；成功空结果能清除旧列表；隐私撤回会停止公开；Steam 旧在线状态在 5 分钟后退出展示。
4. 隐藏模块或条目后，公开接口、列表数量、相关文章标签及归档均一致；同步不会重置隐藏设置。
5. 后台能分辨未配置、限流、超时、鉴权失败和过期数据；手动刷新受并发与频率限制。
6. 公开响应和后台页面不泄露凭据；管理写入拒绝错误来源；非法字段、进度和分页参数被拒绝。

一期交付物为上述后端接口、数据库迁移及四个简洁的管理页面。本文只完成设计，具体实现时再按该契约接入页面与来源服务。
